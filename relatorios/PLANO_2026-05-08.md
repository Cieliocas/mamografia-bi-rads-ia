## Plano C — Workspace radiológico (este plano)

Objetivo: o radiologista entra no app e tem **tudo na mão**. Hoje temos 5 abas no menu esquerdo, mas só 2 funcionam de verdade (`images` mostra histórico em memória + estudos persistidos; `patients` lista pacientes). `analysis` e `tools` estão vazias, e `images` deveria ser um navegador de pastas estilo VSCode.

### C.1 — Bug bloqueante: Abrir Imagem não funciona  🔴 PRIORIDADE MÁXIMA

> **Plano separado em `PLANO_FIX_OPEN_IMAGE_2026-05-08.md`** — escrito a seguir.

Resumo do diagnóstico: o frontend chama `App.OpenFileDialog()` (Wails binding), recebe um path, e passa para `study.loadNativePath(path, vp, …)` que faz `POST /api/studies` com esse path. Suspeitas:
1. O Go Core dentro do `.app` bundled não tem permissão de Sandbox para ler arquivos fora de `~/Library/Containers/AIdentify/`.
2. `dicom_reader.go` pode estar falhando silenciosamente em formatos comuns (DCMTK não bundled no `.app`).
3. O image element no Angular pode não estar carregando o `previewURL` (CORS, content-type).

→ Investigar com logs reais do Go Core via `Console.app` antes de codificar.

### C.3 — Aba **Files** — file tree estilo VSCode  🔴 alta

**Por quê:** abrir DICOM um por um pelo file picker é doloroso. Radiologistas trabalham com pastas de pacientes (ex: `~/exames/2026/Maria_Silva/CC_R/img001.dcm`).

**Renomear** a aba atual `images` → `files`, com semântica de explorador:

- **Backend** novo endpoint `GET /api/fs/list?path=<dir>` que retorna:
  ```json
  {
    "path": "/Users/.../exames",
    "entries": [
      {"name": "Maria_Silva", "type": "dir", "size": 0, "mtime": "..."},
      {"name": "img001.dcm",  "type": "file", "size": 12500000, "mtime": "..."}
    ]
  }
  ```
  Restrições: não listar fora do `$HOME` ou de uma whitelist (`~/Pictures`, `~/Documents`, `~/exames`, externa selecionada).
- **Frontend** `<app-files-panel>`:
  - Header: campo "Pasta atual" + botão "Abrir pasta…" (chama `runtime.OpenDirectoryDialog` do Wails)
  - Tree view colapsável: pastas (chevron + ícone), arquivos (ícone por extensão)
  - DICOM/imagem clicável → `viewer.openPath(filePath)`
  - Atalhos: `←`/`→` colapsa/expande; duplo-clique abre pasta; Enter abre imagem
  - Persistir última pasta aberta em `localStorage`
  - Filtro embutido: input "filtrar arquivos…" no topo do tree
- **App menu macOS** (`File`):
  - "Abrir pasta…" `⌘⇧O` → `runtime.OpenDirectoryDialog` → seta no panel
  - "Fechar pasta" `⌘W` → limpa o panel
  - "Recarregar pasta" `⌘R` (sem ser inferência; remapear)

### C.5 — Aba **Analysis** — métricas e comparação  🟢 baixa

**Por quê:** quando a IA estiver rodando, é aqui que o radiologista cruza ROIs com sugestões. Hoje, com os dados que já temos, dá para entregar valor.

Componente `<app-analysis-panel>`:

- **Resumo do estudo atual**
  - Nº de ROIs, distribuição por BI-RADS (gráfico de barras)
  - Tamanho médio das lesões (px → mm quando houver pixel spacing)
  - Tempo total de anotação (delta entre 1ª ROI e signed_at)
- **Comparativo com estudos anteriores** do mesmo paciente
  - Linha do tempo de BI-RADS por data
  - Diff de findings (novos / removidos / mudou de categoria)
- **Estatística da base** (read-only do backend)
  - Total de estudos, distribuição BI-RADS global
  - Pacientes acompanhados há > 6 meses
- Quando IA estiver online: agreement rate (radiologist vs IA)
